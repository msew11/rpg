# 架构边界（首版）

本文件描述供后续功能验证的设计基线。已实现内容以代码和 `openspec/specs/` 为准；首个原型可以通过 OpenSpec change 调整这里的建议，但必须同步说明原因。

## 当前实现

Godot 4.7.2 项目以 `scenes/main.tscn` 为入口，尚无游戏模拟或地图系统。Windows 桌面可运行与导出。

## 已确认的约束

- 使用 ECS 组织游戏逻辑；等轴视角和 8 方向移动是首批需要验证的行为。
- 玩家应感到处于一个连续世界。地图可以按区块动态加载与卸载，不能依赖切换主场景实现区域移动。
- 单机先行，未来 MMO。当前不实现服务器，但不把权威世界状态固定在画面节点里。

## 建议的模块边界

| 边界 | 职责 | 当前状态 |
| --- | --- | --- |
| 世界模拟（ECS） | 保存实体身份和游戏状态，按固定步长运行移动等系统 | 待实现；组件结构和 ECS 方案待原型确认 |
| 会话接口 | 接收玩家输入命令并提供模拟结果；单机时在本地运行，未来可由服务器接管 | 待验证的设计建议，尚无接口 |
| 世界数据与区块 | 使用稳定区块标识管理地图内容和实体归属；区块卸载不应丢失需要保留的状态 | 待实现；地图制作方式待定 |
| Godot 展示层 | 采集输入，显示等轴地图、实体、动画和镜头；从模拟状态更新画面 | 目前只有占位场景 |
| 持久化 | 保存与恢复需要跨游玩会话保留的世界状态 | 后续阶段；格式和存储方式待定 |

建议的数据流是：`输入 → 会话接口 → ECS 模拟 → 状态结果 → Godot 展示层`。这个边界有助于以后迁移权威模拟，但不等于已解决 MMO 的并发、分区和运维问题。

## 首个原型需验证

- 逻辑世界位置与等轴屏幕投影分离，8 方向移动及斜向速度一致。
- Godot 节点卸载或重建后，实体身份和需要保留的状态仍可恢复。
- 单机输入不直接改动画面节点的权威位置，而由模拟结果驱动画面。

## 暂不决定

不预选 ECS 插件、地图数据格式、网络协议、服务端语言或数据库。首个原型只验证会影响这些选择的边界，不预先搭建完整 MMO 基础设施。
