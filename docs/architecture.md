# 架构边界（首版）

本文件描述供后续功能验证的设计基线。已实现内容以代码和 `openspec/specs/` 为准；首个原型可以通过 OpenSpec change 调整这里的建议，但必须同步说明原因。

## 当前实现

Godot 4.7.2 项目以 `scenes/main.tscn` 为入口。首个单人原型采用无节点引用的最小 ECS：`WorldState` 以稳定整数 ID 管理位置、移动意图、速度和朝向组件；`MovementSystem` 在 Godot 固定物理步中更新逻辑位置。本地会话持有世界与玩家 ID，输入层提交屏幕方向命令，展示层读取位置和朝向。有限的固定测试地面使用 Kenney Isometric Roads 的 CC0 资源，玩家标记与镜头在同一主场景中显示。

## 已确认的约束

- 使用 ECS 组织游戏逻辑；等轴视角和 8 方向移动是首批需要验证的行为。
- 玩家应感到处于一个连续世界。地图可以按区块动态加载与卸载，不能依赖切换主场景实现区域移动。
- 单机先行，未来 MMO。当前不实现服务器，但不把权威世界状态固定在画面节点里。

## 建议的模块边界

| 边界 | 职责 | 当前状态 |
| --- | --- | --- |
| 世界模拟（ECS） | 保存实体身份和游戏状态，按固定步长运行移动等系统 | 已有原型：组件表、稳定 ID 和移动系统；尚未实现通用查询框架 |
| 会话接口 | 接收玩家输入命令并提供模拟结果；单机时在本地运行，未来可由服务器接管 | 已有本地会话；尚未定义联网接口或传输格式 |
| 世界数据与区块 | 使用稳定区块标识管理地图内容和实体归属；区块卸载不应丢失需要保留的状态 | 待实现；地图制作方式待定 |
| Godot 展示层 | 采集输入，显示等轴地图、实体、动画和镜头；从模拟状态更新画面 | 已有有限测试地面、方向标记、连续位置投影和跟随镜头；没有最终动画 |
| 持久化 | 保存与恢复需要跨游玩会话保留的世界状态 | 后续阶段；格式和存储方式待定 |

建议的数据流是：`输入 → 会话接口 → ECS 模拟 → 状态结果 → Godot 展示层`。这个边界有助于以后迁移权威模拟，但不等于已解决 MMO 的并发、分区和运维问题。

## 首个原型的验证

- 逻辑世界位置与等轴屏幕投影分离，八方向输入经逆投影后归一化，斜向逻辑速度一致。
- 玩家展示节点重建后，从同一实体 ID 读取位置和朝向；这只验证视图生命周期，不涉及世界区块卸载或跨会话恢复。
- 单机输入经本地会话更新 ECS，展示节点不保存权威位置。

## 暂不决定

不预选 ECS 插件、地图数据格式、网络协议、服务端语言或数据库。首个原型只验证会影响这些选择的边界，不预先搭建完整 MMO 基础设施。
