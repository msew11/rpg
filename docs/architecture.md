# 架构边界（首版）

本文件描述供后续功能验证的设计基线。已实现内容以代码和 `openspec/specs/` 为准；首个原型可以通过 OpenSpec change 调整这里的建议，但必须同步说明原因。

## 当前实现

Godot 4.7.2 .NET 项目以 `scenes/main.tscn` 为入口，入口脚本 `scripts/main.gd`、本地会话 `scripts/local_session.gd` 位于脚本根目录，手工区块配置脚本 `scripts/cfg/manual_chunk_cfg.gd` 位于 `scripts/cfg/`。`scripts/core/` 提供 C# ECS 框架及父子实体；`scripts/world/` 使用 C# 实现 `WorldManager`、区块生命周期、类型组件及无状态更新系统，内部无状态工具集中在 `scripts/world/utils/`。`MovementSystem` 更新玩家位置和朝向，`ChunkLoadingSystem` 根据玩家位置与配置更新活跃行走区块。`WorldChunkLifecycle` 随加载范围创建或卸载规范区块实体，并经会话缓存读写临时存档；`WorldMath` 计算世界坐标，`WorldEntityTreeCodec` 采集、验证和恢复实体树 JSON，`WorldMonsterQuery` 只读计算活跃行走区块中怪物的回环显示位置。世界实体上的 `WorldChunksComponent` 保存尺寸、活跃规范区块的地块数据和加载范围，`WorldDebugComponent` 保存调试开关。玩家实体直接属于世界实体，活跃区块实体也属于世界实体，区块实体可拥有其子实体。顶层 `scripts/utils/` 的 GDScript 提供无状态展示几何计算；`scripts/ui/` 的 Godot 节点负责绘制与交互。手工测试区块使用 Kenney Isometric Roads 的 CC0 资源。

`Main` 和 `DebugPanel` 将移动、地块、调试开关及测试怪物创建交给当前 `LocalSession` 的语义化方法；会话构造 `WorldCommandEvent` 子类并调用 `WorldManager.send_event()`。展示层仍通过世界管理器读取状态和订阅信号，地图拖动与视野高度只改变 UI。世界管理器私有持有 `EcsWorld`，生产调用方不能通过管理器直接增删实体、组件或 System。`chunks_view()` 与 `debug_view()` 返回持续读取当前状态的只读视图；加载坐标列表和地块数组返回独立副本，展示与存档代码不能通过查询结果改动组件。通用 `EcsWorld` 在系统注册时收集 `[EcsEventHandler(typeof(...))]` 方法，按事件精确类型同步路由。移动意图、测试地块切换、调试开关和调试怪物创建分别由世界 System 处理。`send_event()` 返回只读的 `WorldEventResult`：`handled=false, changed=false` 表示无处理者，`true, false` 表示已处理但未改变状态，`true, true` 表示命令状态已变化。移动意图写入算命令变化，玩家位置与朝向在 `step()` 推进后才变化。世界管理器比较事件处理及逐帧更新前后的玩家、区块和调试状态，只对实际视图变化发出对应信号。新交互可增加事件和处理系统，不需给管理器增加对应命令方法。

启动界面、游戏内保存入口、Chat 面板与五槽位读取界面由 `scenes/main.tscn` 的 UI 层实现。`LocalSession` 在新游戏或读档时通过一次性的 `WorldManager.initialize_session()` 建立玩家与附近区块，运行期不调用零散直接写入入口；位置、朝向和地块等测试布置由 `tests/WorldEcsTestAccess.cs` 承接。`WorkingSaveStore` 管理会话临时增量，`LocalDataRepoCache` 仅经它加载与落地区块；`SaveSlots` 负责五个正式 JSON 槽位的验证和提交。新游戏清理残留工作文件并建立空副本，读档以正式快照建立工作副本；点击保存时 `LocalSession` 将活跃区块与临时记录合并，更新工作文件与指定正式槽位。区块实体及其子树按组件字符串落地和重建，直接销毁实体不触发落地。卸载写入失败时仍释放区块数据，并通过 Chat 系统消息提示可能丢失改动。调试开关和地图拖动偏移不属于存档进度。

## 已确认的约束

- 使用 ECS 组织游戏逻辑；等轴视角和 8 方向移动是首批需要验证的行为。
- 玩家应感到处于一个连续世界。地图可以按区块动态加载与卸载，不能依赖切换主场景实现区域移动。
- 单机先行，未来 MMO。当前不实现服务器，但不把权威世界状态固定在画面节点里。

## 建议的模块边界

| 边界 | 职责 | 当前状态 |
| --- | --- | --- |
| 世界模拟（ECS） | 保存世界与玩家实体状态，按固定步长运行无状态系统 | 已接入共享 `EcsWorld`；玩家状态、区块集合和调试状态由类型组件持有 |
| 会话接口 | 接收玩家输入命令并提供模拟结果；单机时在本地运行，未来可由服务器接管 | 已有本地会话；尚未定义联网接口或传输格式 |
| 通用数据访问 | 由每个本地会话的缓存统一持有具名仓库 | `main` 提供数据契约与 `IEcsWorldData`；当前世界数据由 `EcsWorldDataRepo` 单例仓库承载，详见 [数据层契约](data-layer.md) |
| 世界数据与区块 | 使用规范区块 ID 管理测试地块状态，按玩家所在行走区块维护活跃范围 | 当前手工目录为 4 × 4 个测试区块、每区块 12 × 12 格；活跃窗口在配置中默认为 3 × 3，非活跃地块数组退出内存 |
| Godot 展示层 | 采集输入并绘制等轴地图、实体和镜头；显示系统消息 | 已有方向标记、雷达和可拖动的线框完整地图及 Chat 面板；没有最终动画 |
| 持久化 | 保存与恢复需要跨游玩会话保留的世界状态 | 临时工作文件保留卸载区块增量，五个正式槽位只在点击保存时更新；当前保存玩家位置、朝向及测试地块改动 |

当前原型的数据流是：`输入 → 本地会话及其 DataRepoCache → ECS 玩家与世界实体组件 → World System 更新 → Godot 绘制`。玩家行走坐标持续增长；行走区块对世界尺寸取非负余数得到规范 ID。显示实例使用行走坐标，活跃地块状态按规范 ID 保存在世界实体的区块组件中。同一规范 ID 若被多个行走实例引用，最后一个实例退出后才释放地块。完整地图只按尺寸绘制线框，不读取远处 tile。缓存创建的 `EcsWorldDataRepo` 与 `EcsWorld` 引用同一份 `EcsWorldData`。MMO 的权威状态、并发、分区和运维问题尚未解决。

## 首个原型的验证

- 逻辑世界位置与等轴屏幕投影分离；单键沿屏幕轴移动，双键沿瓦片斜向轴移动，转换后在逻辑世界归一化，八方向逻辑速度一致。玩家方向标记与实际屏幕轨迹一致。
- 玩家展示节点重建后，从同一实体 ID 读取位置和朝向；这只验证视图生命周期，不涉及世界区块卸载或跨会话恢复。
- 单机输入经本地会话更新 ECS，展示节点不保存权威位置。
- 负坐标和越过世界两侧时，规范区块 ID 与区块内地块坐标仍对应；Debug 面板分别控制区块边缘线和雷达显示，F3 是边缘线快捷键，Windows 导出版本也可操作；空格切换地块验证本次运行内状态保留。
- Debug 面板的视野高度滑条将镜头可见高度从默认值放大至 4 倍，仅改变显示，不扩大活跃区块范围。游玩时空格输入先于 GUI 开关处理，点击开关后仍只切换地块；文本输入聚焦时保留空格输入。
- Debug 面板从当前 `SaveSlots.save_dir` 解析并显示正式存档的本机绝对目录；只读路径可选中复制。默认目录同时包含会话临时工作文件。
- 左上角雷达经 `UtilRadarProjection` 读取当前区块与玩家数据；玩家点固定居中，区块描边使用等轴屏幕方向并随连续位置平移，便于观察跨区块与回环。
- 雷达用黄色完整描边当前区块，蓝色、灰色区分已加载与未加载区块；灰色网格覆盖整个雷达视窗并标注规范坐标，粉色标明回环接缝。按 M 打开的完整地图根据配置绘制线框；鼠标拖动仅修改地图视图偏移，不修改世界状态。

## 暂不决定

当前原型采用共享的自建 ECS 核心；未来是否更换实现仍待实际需求验证。地图数据格式、网络协议、服务端语言和数据库均未确定，当前不搭建 MMO 基础设施。
