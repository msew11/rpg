## 3c. 世界边界收口待办

下列各项均未开始。每次只选一项建立独立 OpenSpec change，确认具体接口与验收场景后实施；前一项完成时更新本节状态，再决定是否进入下一项。

1. **收起裸 ECS 入口**：`WorldManager.ecs` 目前允许外部直接增删实体、组件和 System，绕过管理器并可能使区块索引失效。完成条件：生产调用方不能通过世界管理器直接修改 ECS；现有测试仍能验证实体关系与持久化。
2. **提供只读世界查询**：`chunks()`、`debug()` 返回可变组件，调用方可绕过通知修改加载范围、尺寸和开关。完成条件：展示层与存档层取得所需状态，但不能通过查询结果修改世界组件；地块数组仍不暴露内部可变引用。
3. **收口直接写入方法**：位置、朝向、地块 setter 与创建、初始化、卸载入口仍可在运行阶段绕过事件规则。完成条件：区分会话初始化、存档恢复、测试布置和运行时交互；运行时外部交互不再使用这些直接写入入口，区块跟随与通知保持正确。
4. **明确变化通知归属**：事件对象上的公开 `chunks_changed`、`debug_changed` 标记可由发送方伪造，处理 System 漏标也会让视图失去更新。完成条件：只有实际状态变化产生相应通知，重复或无效命令不产生伪通知；玩家、区块和调试视图均有覆盖。
5. **区分事件路由与执行结果**：当前 `send_event()` 的 `true` 只表示有处理方法执行，未加载地块等无效操作也返回 `true`。完成条件：调用方能区分无处理者、已处理但未改变状态、成功改变状态，且结果语义有测试和文档说明。
6. **收拢会话交互接口**：`Main`、`DebugPanel` 目前直接访问 `world_manager` 发送部分事件，移动却经过 `LocalSession`。完成条件：游戏输入与调试操作统一经会话接口提交；视图读取所需状态，地图拖动等纯 UI 行为保持在 UI。
7. **拆分管理器剩余职责**：`WorldManager` 同时负责区块生命周期、临时存档与实体树 JSON，以及怪物可见位置计算。完成条件：分别确认这些职责的归属并迁移独立部分，保存恢复、世界回环和怪物显示行为保持不变。

本次世界 ECS 迁移保留了阶段 1、2 的验收行为。Windows 导出检查因本机缺少 Godot 4.7.2 .NET 导出模板而停在 preset 配置检查；安装匹配模板后仍需验证导出与启动。
