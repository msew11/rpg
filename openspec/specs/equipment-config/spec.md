# equipment-config Specification

## Purpose
为后续角色装备功能建立独立装备配置、稳定槽位类型和代码分类映射，保证所有装备道具的配置引用在启动阶段完整可用，不将配置存在误认为已实现穿戴功能。

## Requirements

### Requirement: 独立装备表与道具引用
系统 SHALL 加载平铺的 equipment.json 数组及对应 Schema，装备记录以正整数 id 唯一索引。武器和防具道具的 relatedId SHALL 指向存在的装备 id；关联由装备缓存整表 Validate 重载在所有配置和索引加载完成后检查，不依赖文件顺序，编写时默认约定道具 id 与装备 id 同值，但不强制相等，允许多个道具引用同一装备。装备记录 SHALL 通过正整数 appearanceId 显式关联项目内持握资源，不承载槽位或未确定的数值属性。

#### Scenario: 有效和共享引用
- **WHEN** 不同道具通过相同 relatedId 引用存在的装备记录
- **THEN** 启动成功，道具和装备可分别通过各自 id 查询

#### Scenario: 装备引用缺失
- **WHEN** 任意武器或防具记录的 relatedId 为零或不存在
- **THEN** 启动失败，错误包含 item.json、道具 id、relatedId 及 equipment.json

#### Scenario: 装备表非法
- **WHEN** 装备表缺失、重复 id、非正 id、无效外观关联、null 行或出现未声明字段
- **THEN** 启动失败并包含配置文件诊断

#### Scenario: 空装备配置
- **WHEN** 道具表和装备表均为空
- **THEN** 启动成功且不自动补建记录

### Requirement: 枚举槽位与代码分类映射
系统 SHALL 以独立枚举定义主手、副手、头、面、身体、项链、手、戒指一、裤子、戒指二和鞋子，共十一种槽位。代码 SHALL 将全部已支持武器（剑、双手武器、法杖、枪、拳刃、暗器）仅映射至主手，防具/盾牌仅映射至副手。普通剑允许搭配盾牌，其余武器占用双手且副手必须为空；盾牌允许单独装备。其余组合无映射，装备表不声明槽位。拳刃和暗器以一件主手装备提供双手持握外观。

#### Scenario: 剑与其他类型
- **WHEN** 查询所有已定义大小类组合的适配槽位
- **THEN** 只有明确绑定的组合适配，全部武器只适配主手，盾牌只适配副手，未知枚举返回不适配

### Requirement: 装备外观动作完整性
装备外观 SHALL 提供男女13个请求动作的项目内资源入口，声明实际来源动作及攻击类别，原生动作保留对应完整帧；缺少来源时明确回退站立。启动 SHALL 检查全部入口存在，错误包含装备记录与缺失路径。

#### Scenario: 原生枪杖与拳刃
- **WHEN** 加载测试木杖、枪、拳刃和飞刀外观
- **THEN** 枪杖具有原生攻击2与准备2，拳刃和飞刀具有原生攻击3与准备3，其他缺失入口明确引用站立而非其他攻击

#### Scenario: 非默认动作缺失
- **WHEN** 外观的死亡、攻击2、攻击3、准备2、准备3或骑乘入口缺失
- **THEN** 启动失败并指出equipment.json记录及缺失路径
