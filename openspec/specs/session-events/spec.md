# session-events Specification

## Purpose

定义会话内基于消息类型的监听契约，保证所有缓存处理完成后界面和世界才读取状态，同时明确注册、释放、重入以及异常行为，使调用顺序不依赖界面和缓存的创建顺序。

## Requirements

### Requirement: 缓存优先的类型监听
事件系统 SHALL 提供按具体类型注册的可释放监听，同一消息先执行全部缓存监听再执行普通监听；每阶段内按注册顺序执行。

#### Scenario: UI 先注册
- **WHEN** UI 在角色缓存之前监听相同响应或推送
- **THEN** UI 回调读取到该消息更新后的缓存

### Requirement: 监听生命周期与重入
事件系统 SHALL 对单条消息使用监听快照；分发期间新增监听仅处理后续消息，已释放监听不得再次执行。嵌套发布 SHALL 排队到当前消息所有阶段结束后执行；会话重置 SHALL 丢弃旧分发剩余监听及嵌套消息。

#### Scenario: 注册和取消
- **WHEN** 监听回调新增监听或释放尚未执行的监听
- **THEN** 新监听不参与当前消息，已释放监听跳过，后续消息使用更新后的监听集合

#### Scenario: 嵌套发布
- **WHEN** 缓存监听发布第二条消息
- **THEN** 第一条消息的普通监听先执行，第二条消息随后完整分发

### Requirement: 分阶段异常隔离
缓存监听失败 SHALL 报告错误并跳过该消息的普通阶段；普通监听失败 SHALL 报告错误并继续其他普通监听。失败不得阻止后续消息。

#### Scenario: 缓存异常
- **WHEN** 缓存处理响应时抛出异常
- **THEN** 普通监听不读取该消息的部分更新结果，后续消息仍可处理

#### Scenario: UI 异常
- **WHEN** 一个普通监听抛出异常
- **THEN** 其他普通监听仍被调用且错误可被观察
