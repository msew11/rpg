# server-actors Specification

## Purpose

定义服务端消息在独立执行单元中的生命周期、顺序和故障边界，使登录、角色和地图能够按身份独立初始化与处理，并为跨单元请求提供可观察的响应和单向通知契约。

## Requirements

### Requirement: 生命周期与串行邮箱
服务端执行单元 SHALL 依次经历 INIT、RUN、STOP，在独立异步任务中逐条处理邮箱；初始化完成前不得调用业务 Handler。停止 SHALL 排空已接纳消息并拒绝新消息。初始化失败 SHALL 进入 STOP，并使所有等待请求收到错误。

#### Scenario: 初始化与停止
- **WHEN** 初始化期间连续发送请求并随后停止
- **THEN** 请求等待初始化后按顺序处理，停止完成后新请求失败

#### Scenario: 故障隔离
- **WHEN** 一个分片加载失败或一个请求处理失败
- **THEN** 对应 Ask 收到错误，其他分片仍可工作；业务请求失败不终止正常分片

### Requirement: 身份分片与按需初始化
服务端 SHALL 启动唯一登录执行单元加载全部角色摘要，角色及地图按消息携带的正整数身份唯一分片。首次客户端请求、Ask 或 Tell SHALL 触发对应分片初始化。角色仅加载自身实体表，读取 MapId 后通过 Ask 初始化地图；无选角或地图消息时不得预读地图。

#### Scenario: 分片独立
- **WHEN** 两个角色属于同一地图，且另一角色实体文件损坏
- **THEN** 两个合法角色独立工作并共用一个地图分片，损坏角色失败不影响登录摘要或其他角色

### Requirement: Ask 与 Tell
执行单元之间 SHALL 支持可等待并可回调处理结果的 Ask，以及无需业务回复的 Tell；两者共享同一顺序邮箱。跨单元不得共享可并发修改的业务状态。

#### Scenario: 通知与回调
- **WHEN** Tell 更新状态后发送 Ask 并注册结果处理
- **THEN** Ask 观察到更新并执行结果处理，Tell 无需等待业务回复
