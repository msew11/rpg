# Design

## Context

通用 `EcsWorld.SendEvent()` 的布尔值只表示至少一个处理方法执行。`WorldManager` 已比较事件前后的玩家、区块和调试可观察状态，并据此发信号；移动意图组件不在该视图快照中。

## Goals / Non-Goals

**Goals:** 在世界边界组合路由结果与命令状态变化，向 C# 和 GDScript 调用方提供只读、语义明确的结果。

**Non-Goals:** 不改变通用 ECS 路由、不把逐帧世界推进混入本次命令结果、不提前发玩家视图通知，也不收拢会话入口。

## Decisions

- 返回 Godot 可读取的 `WorldEventResult`，以只读 `handled`、`changed` 属性表达三种有效组合。相比直接用枚举，GDScript 和 C# 调用方均能直读含义；`changed` 为真时 `handled` 必为真。
- 事件前后分别读取当前移动意图，结合已有可观察状态比较判断 `changed`。移动方向首次变化算命令状态变化，但不触发玩家视图信号；重复方向、无效实体不算变化。
- 保持 `EcsWorld.SendEvent()` 的布尔路由契约。世界入口不再返回布尔值；当前生产调用方未读取返回值，已有布尔断言测试改为检查两个结果属性。

## Risks / Trade-offs

- 每次事件额外复制移动意图并创建一个结果对象 → 当前世界只有少量实体；若未来高频输入形成性能问题，可在保持结果契约的前提下优化快照。
- 新增命令若修改新的非视图组件，现有比较可能遗漏 → 为该命令纳入所需状态并增加结果测试。
