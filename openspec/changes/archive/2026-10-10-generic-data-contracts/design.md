# Design

## Context

main 尚无数据模块或正式提供方。目标与范围见 proposal.md，行为要求见 `data-access` 增量规范。

## Goals / Non-Goals

**目标：** 提供可替换的 GDScript 数据源契约，并以测试替身验证其可观察行为。

**非目标：** 正式持久化或内存持有、数据模式、领域标识及玩法规则。

## Decisions

- 使用 `RefCounted` 抽象基类、`StringName` 键和 `Variant` 值。后续调用方可以注入数据源，无需场景节点或自动加载单例；节点和单例会提前决定生命周期与场景归属。
- 同时提供 `has_value` 与 `read_value`，以区分缺失键和已存储的 `null`。统一返回结果对象会使每次读取都需要拆包。
- `write_value` 返回是否发生有效变化。发生变化时，提供方发出一次 `value_changed(key, value)`；相等值写入不发信号。这样可直接测试无变化写入和通知行为。提供方负责其支持值的相等性判断；初始替身覆盖普通 Variant 值。
- 内存字典只放在 `tests/`。抽象契约不持有状态，因此 main 不提前选择正式提供方。

## Risks / Trade-offs

- [后续提供方需要领域专用键] → 在提供方边界转换标识，或通过后续独立 change 修订契约和验收场景。
- [引用型值可被绕过写入操作直接修改] → 文档要求消费者再次调用 `write_value` 才能得到通知；契约不承诺深层变更追踪。

## Migration Plan

当前没有既有调用方或数据需要迁移。回滚该功能提交即可撤销契约。
