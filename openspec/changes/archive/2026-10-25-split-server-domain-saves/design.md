# Design

## Context
DataServerRole 是内存聚合，包含角色与背包，RepoServerRole 目前整份序列化。MockServer 已区分移动、GM 和物品移动提交位置。

## Goals / Non-Goals
只降低相关领域的写入量，不增加玩法、协议或多人数据库。客户端设置文件不变。

## Decisions
- role 文件保存角色属性、位置、版本及墓碑，序列化时排除 Bag 与 BagExtraRows；bag 文件使用带 RoleId 的独立 DTO，保存 BagExtraRows 与完整 DataServerBag。
- 保留聚合 Load/Save 接口，并增加 SaveRole/SaveBag。移动与删除用 SaveRole；GM 与物品移动用 SaveBag。通用 Save 仅替换变化领域，主动状态更新保持兼容。
- Load 组合新两份文件，缺失、损坏或身份不符报错。只有两份领域文件都不存在时读取旧 id.json；读取旧格式不写盘，首次保存产生完整分域存档，旧文件作为备份保留。任一新领域文件一旦存在不得回退旧数据。
- 目录按 role 与旧文件枚举并按 ID 去重，bag 与临时文件不成为角色。墓碑优先，旧文件不复活角色。
- 单领域正常更新使用同目录临时文件刷盘和替换，不读取或重写另一领域。首次保存、迁移及两个领域共同更新采用 `<id>.pending.json` 回滚记录，保存原文件文本或缺失状态；记录先刷盘，各目标替换后删除记录作为提交点。失败回滚，进程中断后首次读写先恢复未提交记录；全部成功后才输出各目标 IO 日志。记录仅允许 role/bag 键，不接受任意路径。

## Risks / Trade-offs
- 多文件无法用一次重命名完成提交，回滚记录保证后续访问前恢复；不可恢复的磁盘错误明确报错，不暴露部分聚合。
- 保留旧文件占用额外磁盘，但避免无授权删除；迁移后不会继续重写它。
- 仅面向单进程 Mock，不提供并发进程协调；继承现有单文件替换的操作系统持久性边界。

## Migration Plan
兼容读取旧文件，首次业务保存迁移。回滚代码时应使用保留的旧文件或从分域文件还原，旧文件不会含迁移后的业务更新。
