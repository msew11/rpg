## MODIFIED Requirements

### Requirement: JSON 角色持久化
服务端 SHALL 在 user://server 使用 `<角色ID>.role.json` 和 `<角色ID>.bag.json` 分别保存角色及背包领域。角色移动与删除只提交 role，GM 和物品移动只提交 bag；单领域正常提交 SHALL 不读取或重写另一领域。成功替换文件后才提交内存并响应或推送。创建、迁移及同时变更两领域 SHALL 在失败时回滚，中断后访问前恢复未提交状态。全新目录保持空列表，删除保留墓碑且编号不复用。旧 `<角色ID>.json` SHALL 可读取，首次保存迁移并保留旧文件；新格式存在时不得回退旧数据，分域缺失、损坏或身份不符 SHALL 明确报错。

#### Scenario: 重启与角色隔离
- **WHEN** 角色移动确认成功后重建服务端并重新选角
- **THEN** 恢复最后确认的角色状态，其他角色数据保持独立

#### Scenario: 存档损坏
- **WHEN** 登录或选角读取到损坏、不合法或身份不符的角色文件
- **THEN** 返回明确错误且不覆盖原文件

#### Scenario: 保存失败
- **WHEN** 移动或主动更新无法写入存储
- **THEN** 不返回成功、不推送成功状态，已确认内存数据和原有效文件保持原值，并报告错误

#### Scenario: 按领域写入
- **WHEN** 角色移动、GM 发放或物品移动成功
- **THEN** 只有对应 role 或 bag 文件发生写入，另一领域文件及其 IO 日志保持不变

#### Scenario: 旧文件迁移与墓碑优先
- **WHEN** 首次保存旧单文件角色，之后重启或删除
- **THEN** 生成完整分域文件且保留旧文件，背包与属性保持，旧文件不覆盖新领域也不恢复已删除角色

#### Scenario: 多文件中断与损坏隔离
- **WHEN** 创建或迁移中途失败或进程中断，或分域文件缺失、损坏及角色 ID 不符
- **THEN** 失败不提交部分角色，后续访问先恢复未提交状态；无回滚记录的分域损坏明确报错，不回退旧备份
