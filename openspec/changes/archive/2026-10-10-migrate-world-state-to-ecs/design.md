## Context

`EcsWorld` 按实体 ID 和组件脚本类型保存组件，并按注册顺序调度 `EcsSystem`。当前玩家已使用 ECS；区块数据仍在 `WorldState._values`，展示节点直接通过键访问数据并计算雷达和地图几何。

## Goals / Non-Goals

- 目标：World Entity 持有一个世界区块组件，所有规范区块地块数据都保存在该组件中；玩家数据继续由玩家实体组件管理。
- 目标：消除产品代码对 `WorldState` 具名键接口的依赖，以明确类型的组件和操作连接模拟与视图。
- 目标：雷达与地图的坐标、可见范围和状态分类由 System 计算，节点只处理绘制与输入。
- 非目标：改造共享 ECS 核心、持久化、联网、地图内容或视觉设计。

## Decisions

- `WorldState` 保留为本地 ECS 会话的薄封装，创建 `world_entity_id` 并提供类型明确的组件访问与状态变更通知。它不再继承 `DataSource`。
- 世界区块组件保存尺寸、规范区块到地块数组的映射和当前加载的行走区块。一个组件实例覆盖全部区块；调试显示开关由世界实体上的独立组件保存。
- 区块管理仍使用当前的测试目录与坐标规则，通过组件读写。数组对外读取使用副本，修改由明确方法提交，避免绕过变化通知。
- 雷达与地图 System 保持在 ECS 层，接受视窗尺寸等展示参数并生成用于绘制的几何和状态；节点保留 Godot 绘制和鼠标拖动逻辑。
- 用领域信号通知玩家、区块与调试状态变化，替代由字符串键驱动的通用通知。

## Risks / Trade-offs

- 全量迁移会触及多个测试和视图脚本；以现有行为断言及项目检查验证回归。
- System 需要知道雷达与地图的像素尺度；这些参数作为展示配置传入，不改变世界权威状态。

## Verification

- 检查 World Entity 的组件归属、类型化读取和区块副本隔离。
- 运行现有移动、区块、雷达和地图测试及 `tools/check.ps1`，核对无产品代码继续调用具名键接口。
