# Design

## Context

世界区块与调试组件由 ECS System 和 `WorldManager` 修改。GDScript 展示、工具与存档代码通过 `chunks()`、`debug()` 读取属性和方法；现有地块读取已经复制数组，`loaded` 则返回同一可变集合。

## Goals / Non-Goals

**Goals:** 让现有读取调用继续取得最新世界状态；防止通过查询结果写入组件；保留地块数组隔离和视图通知行为。

**Non-Goals:** 限制会话缓存、测试观察器或直接写入方法；这些属于其他边界项。

## Decisions

- 增加 `WorldChunksView` 和 `WorldDebugView`，仅暴露只读属性与查询方法。管理器在构造时绑定组件并缓存视图，避免频繁创建包装对象。相比每次复制整个区块数据的快照，持续读取当前组件更适合逐帧视图与存档合并。
- `loaded` 每次返回新集合；`tiles_for` 继续调用组件已有的复制方法。两种返回值即使被修改，也不触及 ECS 内的数据。
- 管理器内部通过私有组件访问器读取和写入，公开 `chunks()`、`debug()` 只返回视图。测试从会话仓库确认组件继续由 ECS 持有，并检查查询视图没有可写成员、列表和地块副本不能改动内部状态。

## Risks / Trade-offs

- 只读视图持续反映最新组件状态，调用方分多次读取时可能跨越一次世界更新 → 当前世界更新同步执行；逐帧雷达仍按既有方式集中读取一次需要的值。
- 每次读取 `loaded` 都复制少量活跃坐标 → 活跃窗口目前有界；已有绘制调用无需持有可变引用。
