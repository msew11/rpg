# Design

## Context

`WorldManager` 当前公开 `EcsWorld ecs`，但生产调用方只使用管理器的命令、读取和信号。测试直接用 `ecs` 读取实体树、布置任意子实体并验证落地。`LocalDataRepoCache` 已为会话持有 ECS 数据仓库。

## Goals / Non-Goals

**Goals:** 从世界管理器 API 移除可写的 ECS 对象；保留实体关系、区块卸载和正式存档的现有验收。

**Non-Goals:** 重设计可变组件查询、直接写入方法或事件结果语义；这些各有后续独立 change。

## Decisions

- `WorldManager` 将 ECS 设为私有字段，内部系统及区块索引继续使用同一实例。相比新增一个仅靠约定禁止写入的包装属性，编译期访问限制更明确。
- 测试在 `tests/` 内通过会话缓存构造指向同一仓库数据的 `EcsWorld` 观察与布置器。相比给生产管理器新增测试专用写入方法，此方式不扩大生产世界 API。测试布置器不注册系统，也不参与 `step()`。
- 保留已有集成测试中的任意子实体布置和销毁场景，确保落地与实体树回归可以直接观察；`WorldManager` 的公开成员检查加入世界 ECS 测试。

## Risks / Trade-offs

- 测试布置器可绕过管理器索引 → 仅用于已存在的区块实体之下，不修改世界和区块实体本身；生产目录没有调用它。
- 这次只封闭 `WorldManager` 的 ECS 属性，缓存和组件查询的更大边界仍按路线图后续项处理。
