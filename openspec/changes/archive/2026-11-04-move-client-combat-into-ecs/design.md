# Design

## Context

见 proposal.md。现有 WorldManager 按固定帧执行单个移动系统，MovementSystem 直接写动作；WorldService 在此之后推进攻击并覆盖快照。CombatCache 已过滤网络攻击版本和重复命中，MapCache 保留增量基线与死亡覆盖层。服务不得订阅协议，测试含独立世界、Godot xUnit、真实输入及 TCP 双进程。

## Goals / Non-Goals

**Goals:** 世界可在不依赖网络/配置服务时独立推进攻击；网络缓存继续验证权威数据；现有操作、编号顺序和玩法保持。

**Non-Goals:** 不改变服务端 Actor、协议、伤害规则，不引入通用 ECS 框架、AI、血条或新动画。

## Decisions

- 组件分为 DataCombatIntentComponent、DataAttackComponent、DataCombatCooldownComponent、DataAttributesComponent、DataHealthComponent；世界时钟保存统一毫秒时间。单次攻击保留不可变快照、响应等待和取消/权威版本，即使动画结束也不丢失等待和墓碑。冷却独立防止取消后提前起手。相比合并一个战斗对象，分开可明确生命周期。
- WorldManager 持有走近、移动、攻击和动作系统实例，顺序显式固定；移动组件保存移动结果，动作系统唯一合成最终 Motion/Facing。远端同步只写基础动作，权威攻击组件优先。保留显式非移动动作验收入口。
- WorldService 将有效输入转换为 Action，输入阶段 FlushActions 处理取消/走近并合成动作，不推进时钟或自动起手。固定帧推进时间与全部系统。世界统一分配移动/攻击/取消序号，出站队列保存顺序，服务接回移动限流和确认机制。相比 Tick(0)，单独处理输入避免重复自动起手。
- Session 战斗缓存增加已验证通知交接队列，服务转换为开始、取消、响应和命中 Action。网络格式验证与接纳缓存保留；ECS 自己保留当前预测、权威版本及死亡墓碑。远端暂未建立实体时保留权威攻击记录，进入后挂入组件，离开清理。
- 属性和服务器时间经纯数据 Action 输入，不让组件或系统持有 Session/Config。移动速度也从属性数据读取；测试改用数据同步更新速度。每次起手固定动作、时长、命中比例和目标位置。
- 地图组件同步生命且过滤旧版本；命中 Action 可更新血量或销毁实体，世界保存死亡版本防止旧快照复活。伤害队列保存独立位置，重复命中不会再次输出。网络原始增量快照不修改。

## Risks / Trade-offs

- [输入阶段和固定帧处理两次] → 输入不推进时间、不执行攻击系统；事件只能取走一次。
- [同帧取消、移动和迟到响应交错] → 统一编号和 FIFO，取消上界及权威时间/编号共同过滤；回归对应场景。
- [远端位置插值与攻击进度不同步] → 保持现有插值与统一攻击时钟，位置同步不写最终攻击动作。
- [Session 与 ECS 都保存快照] → Session 仅保存接纳结果/原始同步基线，预测和动作推进仅归 ECS；通知队列取走即清空。

## Migration Plan

先迁移组件/系统和事件桥接，再接入生命组件，补独立世界回归并运行完整检查。同步架构与路线图后归档 change，提交一个本地可回滚提交；无需存档迁移。
