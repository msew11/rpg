# Design

## Context

`WorldState` 已按规范区块持有活跃区块实体，子树通过现有临时存档机制保存与恢复。Debug 面板当前只处理显示设置，主场景持有当前会话及玩家位置。

## Goals / Non-Goals

**Goals:** 由 Debug 操作创建一个可识别、可落地的 monster 子实体，并把位置限制在触发时玩家所在的行走区块。

**Non-Goals:** monster 的画面、行为、属性、自动生成和战斗。

## Decisions

- Debug 面板发出创建请求信号，主场景仅在游玩模式下以当前玩家位置调用 `WorldState`。这让面板不持有玩家 ID，也让世界层负责实体归属。
- 世界层由连续位置计算行走区块，再映射到活跃规范区块实体。随机位置采用行走区块左上角加上两个区间内的随机偏移，保持负坐标和回环时的坐标含义。
- 新增 `MonsterComponent` 作为身份标记，并让空字符串代表需保留的标记；`PositionComponent` 已支持落地。这样直接使用现有区块子树保存流程。

## Risks / Trade-offs

- 同一规范区块可能同时对应多个行走区块；实体只有一个规范区块父实体，记录的是创建时的连续世界位置。当前无 monster 展示，因此不定义其在其他回环实例中的投影。
