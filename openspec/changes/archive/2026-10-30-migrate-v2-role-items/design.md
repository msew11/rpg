# Design

## Context
见 proposal.md。默认 TCP、三类串行 Actor 和 V2 进入已存在；旧物品链路仍供回归。

## Goals / Non-Goals
实现已确认第一项，地面转移在第二项完成。不扩展玩法、预期版本或去重。

## Decisions
- 原业务 proto 直接进入 Login/Role Handler；通过 GetRoleItems 获取组合快照并同步摘要。运行时在同一物品操作门内完成输出，保证无版本快照顺序。
- 角色规则直接构造不可变三表候选，沿用配置和通用槽位工具，不借用旧 Server 缓存。
- 公开投影版本从移动缓存独立出来；World 按内容区分位置与装备增量，沿用世界帧序号。
- 内部物品调用保留已执行结果以完成编排，对外仍按原身份过滤。保存共用物品入口，不增加分组框架。
- UI 分开判断角色物品与地面能力，直接接纳 V2 消息，复用控件交互。

## Risks / Trade-offs
单实例物品操作串行，保存期间等待；按最新状态执行可能与拿起时不同，属于已确认语义。
