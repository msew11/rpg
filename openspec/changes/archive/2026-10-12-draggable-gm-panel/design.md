# Design

## Context

主场景的 `RadarLayer` 同时包含 DebugPanel、雷达和游戏按钮；`DebugPanel` 负责会话绑定，`PlayerView` 只播放待机和行走。已有动作图片每个模板具备奔跑、攻击、交互、跳跃与转身。视野高度由面板滑条控制镜头缩放。

## Goals / Non-Goals

**Goals:** UI 状态留在展示层，不改世界 ECS 或存档；保持雷达位置独立于面板。

**Non-Goals:** 动作演示不触发战斗、移动或世界事件；不持久化 GM 面板位置和钉住状态。

## Decisions

- 在主场景新增 GM 按钮，面板脚本统一管理入口、拖动、钉住与收起状态。拖动按全局鼠标坐标计算并夹在视口内，避免位置丢失。面板标题栏作为拖动区域，钉住按钮不触发拖动。
- 使用 `TabContainer` 承载世界、角色、存档控件；现有会话绑定和信号继续通过同一面板脚本，减少迁移风险。
- 雷达视图不再读取世界雷达开关决定可见性，保留世界层旧字段以兼容现有存档与核心事件接口。将雷达场景位置设为固定左上角。
- `PlayerView` 维护独立的演示动作状态，由 GM 面板发信号设置；换模板时重置演示与选择框。图片的帧数按实际宽度和帧边长计算，转身图仅有一行。
- 主场景在未处理的游玩滚轮输入中调整滑条值，复用滑条变化信号和范围。

## Risks / Trade-offs

- [窗口缩小时控件可能部分超出] → 拖动和视口尺寸变化时夹紧位置。
- [动作素材帧数与现有待机不同] → 按纹理尺寸计算帧数，并对跳跃素材使用素材实际行高。
