# Design

## Context

`NetService` 是主线程使用的普通 C# 实例，持有队列、传输和事件系统。`MainController` 创建及推进网络，`GameSession` 借用同一实例并以代次保护账号所有权。动机见 proposal.md。

## Goals / Non-Goals

减少运行调用链的网络参数传递，并保留测试的实例隔离和会话绑定。仅开放当前已确定的网络服务，不引入容器、Autoload、懒创建、线程安全承诺或其他全局业务状态。

## Decisions

- `Rpg.Services.GameServices` 提供只读 `Net` 与 `IsInitialized`，`Initialize(NetService)` 返回 `IDisposable` 所有权句柄。入口只登记已创建实例，启动流程决定传输和存储位置；与将 NetService 静态化相比，保留独立测试和可替换传输。
- 注册时检查空值、已释放实例及重复初始化。成功才转移所有权；失败的实例由调用方释放。句柄清空入口后释放服务，幂等且按注册对象身份判断，旧句柄不能清除新服务。
- 主控制器仅持有服务释放句柄，使用 `GameServices.Net` 订阅、发送、固定帧推进；统一清理方法先释放会话和监听，最终释放服务。启动失败也执行相同清理，未获得句柄的主控制器不干扰已有注册。受保护的 `CreateNetService` 创建边界支持场景替身在注册后模拟失败；底层传输关闭异常也通过 finally 清理队列及事件。
- 新增 `GameSession(LoginRt)` 委托给现有显式实例构造，将全局网络捕获到私有字段。操作前检查已释放网络及代次；不得每次操作动态取全局服务，否则旧会话可能使用新连接。
- 全局入口测试集中于同一 xUnit 测试类，其他测试继续使用独立实例。场景冒烟覆盖主场景卸载、重建和再次登录，避免全局状态跨场景残留。

## Risks / Trade-offs

- 静态入口隐含依赖和初始化顺序 → 不自动创建，错误包含明确说明，启动流程统一注册。
- 旧会话碰到重启后的同值代次 → 捕获旧实例并先检查其释放状态，验证旧会话不能改变新网络队列。
- 场景启动异常残留注册 → 统一清理与 finally 释放句柄，异常路径和场景重建验收覆盖。
- 全局入口跨测试共享 → 全局测试集中串行执行，现有网络和会话测试保留实例注入。

## Migration Plan

先增加入口和生命周期测试，再接入主控制器与无网络参数的会话构造、场景回归和当前文档。完整检查通过后同步规格、归档 change 并本地提交。回滚同一提交可恢复显式参数传递。
