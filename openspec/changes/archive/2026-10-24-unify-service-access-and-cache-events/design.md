# Design

## Context

见 proposal.md。服务初始化完成后才发布完整注册，Session 的正式构造不创建缓存，登录请求前才创建缓存。测试目前直接传事件服务给缓存；完整配置加载依赖 Godot。

## Goals / Non-Goals

统一入口并移除缓存保存的服务引用。保持固定依赖顺序和撤销入口后的清理，不添加容器、提前事件注册、测试专用运行分支或新的生命周期。

## Decisions

- Net、Events 和其他访问器统一为 Current 属性读取；IsInitialized 仅检查注册，服务方法负责已释放检查。
- CacheBase.Subscribe 从 GameServices.Events 订阅，仅保存句柄；Dispose 不访问全局状态。删除缓存事件构造和 Session 的事件字段及参数。
- 缓存相关测试复用 GameServicesTestFactory 注册完整服务组，并在现有 Godot 宿主运行。纯事件、网络测试仍保留独立事件生命周期。以独立测试基类管理注册和临时目录，不修改正式配置加载。
- 已有响应的 Session 内部构造仍保留，仅移除事件参数，调用必须在注册后进行。无注册清理回归改为先创建并登录再撤销注册，验证清理结果；缓存独立句柄的清理覆盖无注册场景。

## Risks / Trade-offs

- 缓存无法在未注册时订阅 → 测试统一先注册，正式登录路径已满足。
- 缓存测试需要引擎 → 使用已有 Godot 测试流程；不增加反射造对象或配置读取旁路。
- 保留缓存跨重启后新增订阅会取得新事件域 → 缓存属于当前 Session，随注册释放；释放后新增订阅仍报已释放错误。
