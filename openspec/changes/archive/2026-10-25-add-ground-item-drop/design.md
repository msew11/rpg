# Design

## Context

背包由角色仓库缓存、地图由 ServerMap 持有；两者独立落地。见 proposal.md。静态服务拓扑保持九个，协议监听仍限 CacheBase 与 UI。

## Goals / Non-Goals

以最小专用提交协调实现两侧守恒，不引入通用事务框架、后台线程、拾取或地图对象 ECS。

## Decisions

- DropItem 仅传 role_id、instance_id、count、expected_revision，响应给成功/错误及对象 ID；缓存仍走既有 BagChangedNotice 和 MapAoiNotice。服务器冻结当前权威位置，完整校验候选后同步提交两侧内存，再发通知。版本校验阻止重复扣除。
- MockServer 记录 mapId 到参与角色集合（当前无传送，同一角色不能跨地图）；同一地图共享一个提交组，未关联领域按原逻辑落地。仓库提供写待写状态与确认标记的窄接口，不相互持有。
- 专用 RepoServerItemTransfer 保存 server/item-transfer.pending.json：格式版本、正整数地图 ID、参与角色 ID，以及角色 role/bag/pending 和地图 manifest 的提交前文本（不存在用 null）。路径仅由合法 ID 和固定后缀生成，不接受任意文件路径。一次同步只处理一个组。
- 先原子写回滚记录，再写参与角色待写领域和地图待写块/清单，期间禁止旧块清理；最后删除回滚记录作为组提交点，再清待写标记和关系，最后清理地图旧块。日志延迟到组提交后输出。失败或启动在任何业务仓库读取前幂等恢复旧文件，保留记录直至全部恢复。旧块一直保留，因此无需复制全地图。角色仓库自己的迁移回滚文件也在备份中，避免嵌套恢复覆盖外层结果。
- BagControl 在未被 UI 消费的地图点击时打开数量确认，确认时再次校验冻结的角色、实例与版本；默认整叠，可选部分，取消不发包。确认窗口及点击均隔离世界输入；关闭、刷新或离树使确认失效。
- GroundItemsView 是世界下只读 Node2D，引用 MapCache 不复制物品业务状态；按稳定 GUID 复用表现子节点，按等轴投影放置图标和文本。图标解析与既有资源目录模型放入 Items 供 UI 和世界共同使用，避免反向依赖，不建新服务。同落点对象仅在表现上错开，权威坐标保持。

## Risks / Trade-offs

- 同地图涉及多个角色时共同失败 → 仅阻塞有关组，其他领域继续落地并汇总异常。
- 同步文件 IO 和首次加载仍有容量限制 → 不扩展到后台或跨进程事务，保持现有单进程边界。
- 清理失败发生在组提交后 → 不撤销成功组，下次检测重试旧块清理。
- 硬件断电持久性沿用系统文件边界，尚未落地的成功响应仍可能随异常退出丢失，但两侧一起恢复。

## Migration Plan

协议追加，原存档无需预迁移；启动先恢复新的专用事务记录，再由原仓库执行既有迁移。回滚代码版本前应正常关闭并确认没有未完成事务记录。
