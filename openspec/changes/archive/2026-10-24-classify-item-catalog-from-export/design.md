## Context

用户指定的 HTML 内嵌轻量数据，同目录 items.json 保存完整记录。网页父类型顺序为武器、防具／饰品、其他装备、宠物、收集品、消耗品，子类型在父类型内按 type_code 排序。来源 README 明确装备语义为推定、图标为编号候选，不可按区间0/1直接区分武器和防具。

## Goals / Non-Goals

**Goals:** 默认清单与网页分类、子类型、记录数一致，可搜索名称/ID/说明，查看来源与图标；保留全部素材浏览。

**Non-Goals:** 不把推定语义提升为已确认玩法；不实现背包、穿戴、属性计算或原始二进制解析。

## Decisions

- 新增独立清单导入工具，读取 items.json，输出项目内 definitions.json 与来源哈希记录；不复制原始十六进制大字段，不重新生成现有图集。
- 分类直接使用 display_category，子类型使用父类型内的 type_code/type_name；source + source_row 是唯一记录键，不按道具 ID 去重，保留原始顺序。
- icon_candidate 去除固定 ../art_export/ 前缀后与现有 PNG 来源路径精确关联。不以道具 ID 猜图，不把 avatar_resource 当作图标。477 条缺少候选的记录显示无图占位；21,315 条候选均命中现有图集。
- 图鉴以道具清单为默认模式，另有素材预览模式；父分类改变重置子类型，模式/分类/搜索变化重置页码和详情。每页继续限制48条，详情可滚动。
- 详情显示名称、ID、父/子类型、原码、背包归属、说明、分类与类型确认程度、来源行、候选图标来源。缺图清空上次预览，避免串图。

## Risks / Trade-offs

- [不同表或同行含重复ID] → 使用来源行作为唯一键并完整展示，搜索可返回多个同ID记录。
- [分类和图标尚有推定] → 保留来源状态，界面明确候选提示，不引入游戏规则。
- [记录与素材计数含义不同] → 切换模式明确区分21,792条道具记录与22,872条图片素材。
