# Design

## Context

见 proposal.md。地图对象已有 string MonsterTypeId、稳定 GUID、chunk 存档、九块 AOI 和 ECS 对象。当前 GroundItemsView 跳过怪物；聊天已有命令候选与键盘消费。正式 GM 路由遵循 Login→Role→World，所有 GM 已受物品/保存信号量串行保护。

## Goals / Non-Goals

**Goals:** 让本地选择状态与服务器创建分离，使用同一配置和原始贴图锚点驱动缩影与正式世界展示。

**Non-Goals:** 不建立新全局服务、不增加怪物属性或 AI、不更改公共地图与 GM 消息字段、不加入连续刷怪或碰撞规则。

## Decisions

1. 使用 `monster.json`、`MonsterCfg`、`MonsterCfgCache` 及同名 Schema，配置 ID 使用 int 与整型字典键；候选事件、内部创建消息同样使用整型，现有地图协议与存档的 string MonsterTypeId 仅在边界转换为规范十进制文本；首条 `1001` 树妖，资源取 M201 站立首帧。配置包含 texturePath、anchorX/Y，虚影和正式怪物均使用原图尺寸与相同锚点，共享世界画布相机变换，仅透明度不同。直接复用导出 PNG，避免重新生成美术。
2. 聊天 `/monster` 显示怪物候选；鼠标只选择怪物，回车确认后通过 HUD 事件通知 MainController。独立放置控件拥有预览，主控制器仅在未被 UI 消费的地面输入中确认落点；全局右键可在 UI 上取消。
3. 放置控件将鼠标事件视口坐标按当前 canvas transform 逆变换再转逻辑坐标，并按正式怪物相同的投影定位虚影；每帧以最新鼠标坐标重算，保证静止鼠标下相机平移和缩放仍对齐。主控制器直接使用虚影 LogicalPosition 校验并发送，不独立计算落点；越界拒绝而非裁剪，避免无意放到边缘。落地后立即清除本地状态，发送单次 `monster ID X Y`，服务端失败通过原有聊天反馈。
4. Role GM 校验命令并转发内部 `CreateMonster` 给当前地图，World 邮箱校验配置和边界、提交对象并标记观察者变化。成功复用 GmRt；路由避免无意义背包通知。
5. MonstersView 读取 ECS 不可变对象快照，按 GUID 复用 Sprite2D，使用配置脚底锚点及 Y 排序。服务器正常保存路径已覆盖地图，无需新增持久化格式；已有未知怪物类型不新增启动兼容约束，表现跳过未配置类型。

## Risks / Trade-offs

- [输入重叠] → 放置优先于移动/拾取，UI 左键交给 GUI，全局右键仅在预览时消费；真实视口输入验证。
- [摄像机变换] → 虚影与正式贴图共享世界变换，逐角对比 0.5、1、2、1.75 倍缩放及平移后的可见矩形，并精确比较请求与服务器对象坐标。
- [仅首帧展示] → 当前需求为贴图放置，动画、AI 与战斗保持待定。
- [配置增加影响隔离测试] → 更新复制完整配置的测试夹具，运行统一检查与测试。

## Migration Plan

配置与素材同包发布；不迁移现有地图对象格式。回滚该提交即撤销配置与创建入口，既有存档数据保持原格式。
