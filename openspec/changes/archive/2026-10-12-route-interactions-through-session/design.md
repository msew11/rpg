# Design

## Context

`Main` 直接构造地块、F3 与怪物事件；`DebugPanel` 持有 `WorldManager` 并发送调试开关事件。`LocalSession` 只封装移动命令，展示视图通过世界管理器读取状态与订阅信号。

## Goals / Non-Goals

**Goals:** 当前会话统一构造和提交生产交互，UI 不直接调用 `WorldManager.send_event()`；保留现有快捷键、面板和视图行为。

**Non-Goals:** 不隐藏所有世界读取接口、不重做 UI 数据绑定、不改变地图拖动和镜头参数的归属，也不修改世界事件规则。

## Decisions

- 在 `LocalSession` 增加语义化方法：切换玩家地块、设置或切换调试开关、创建测试怪物；已有移动方法也返回世界事件结果。相比仅增加通用 `submit_event()`，UI 不需要知道事件类型或填写玩家位置、实体 ID。
- `DebugPanel.bind()` 接收会话；面板从其世界读取调试状态和信号，写入则调用会话方法。重新绑定新游戏或读档会话时断开旧世界信号并换用新会话。
- `Main` 保留模式与输入焦点判断；符合条件后调用会话方法。怪物按钮仍由面板发出请求、由 `Main` 判断游玩模式后提交。

## Risks / Trade-offs

- 会话方法随目前具体交互数量增加 → 当前仅封装已确定的原型操作；后续新交互按已确认的需求扩展。
- 展示节点仍持有世界管理器以读取状态 → 在本项范围内检查 UI 不再调用其 `send_event()`，只读视图的更深隔离另行决定。
