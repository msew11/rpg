# Spec Delta

## Purpose

定义并行 V2 框架的 Actor 运行契约，以独占状态、类型化消息、身份分片和有序终止支撑后续模块接入；本能力仅约束 V2，不改变旧 Server 的运行行为与现有客户端入口。

## ADDED Requirements

### Requirement: V2 串行邮箱与故障隔离
V2 执行单元 SHALL 在 INIT 初始化完成后进入 RUN，依序处理 Ask 与 Tell，跨 await 不重入；停止 SHALL 排空已接纳消息并进入 STOP。初始化失败 SHALL 使全部等待者失败；单条处理失败不得终止正常邮箱。Ask SHALL 返回类型化结果，Tell 错误 SHALL 可观察。

#### Scenario: 顺序与停止
- **WHEN** 初始化期间依次投递通知和请求并要求停止
- **THEN** 初始化完成后按接纳顺序处理，停止等待全部回合，后续投递失败

#### Scenario: 故障隔离
- **WHEN** 一个分片初始化失败或一个回合处理抛错
- **THEN** 等待者收到错误，其他分片继续工作，正常分片后续消息继续处理

### Requirement: V2 唯一分片与状态边界
V2 SHALL 按规范账号键、正整数角色 ID、正整数地图 ID 唯一创建分片，按需初始化；调用方 SHALL 通过消息引用访问 Actor，不取得其可写状态。跨单元消息 SHALL 只携带独立或不可变数据，不携带操作委托或业务上下文。

#### Scenario: 并发取得分片
- **WHEN** 并发请求同一身份及其他身份的分片
- **THEN** 同一身份返回同一活动引用，独立分片可并行处理，未收到消息的分片不执行初始化

### Requirement: V2 宿主边界
V2 SHALL 与旧实现并存，支持独立创建、接收字节、读取输出及异步关闭。关闭 SHALL 先停止接纳外部工作，等待已接纳工作完成，再停止 Actor；停止后不得创建新分片。

#### Scenario: 排空在途工作
- **WHEN** 一个请求正在等待 Actor 回合时关闭宿主
- **THEN** 关闭等待该请求完成，不因提前停止下游 Actor 而丢失已接纳回合
