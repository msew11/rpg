# Design

## Context

`main` 已有通用数据源契约，但没有 ECS；新运行时位于 `scripts/core/ecs/`，不依赖场景节点或玩法类型。目标与可观察行为见 proposal.md 和 `ecs-runtime` 规范。

## Goals / Non-Goals

**Goals:** 小型可实例化的内存运行时；稳定、可预测的生命周期与调度语义；可从普通 GDScript 调用。

**Non-Goals:** 并行执行、组件序列化、系统依赖图、编辑器集成与实体节点绑定。

## Decisions

- `EcsWorld` 使用单调递增的整数 ID 和存活实体表，销毁后不复用 ID，避免旧引用意外指向新实体。与复用 ID 相比，整数增长在当前内存范围内更简单。
- 组件继承 `EcsComponent: RefCounted`，以实际脚本资源为精确类型键；同类型重新附加即替换。与字符串键相比，脚本资源避免拼写冲突；暂不提供继承类型匹配。
- 查询遍历存活实体 ID，返回新的整数数组并按 ID 排序。与维护复杂索引相比，这便于保证确定性与快照语义；未来有性能证据再优化。
- 系统继承 `EcsSystem: RefCounted` 并实现 `update(world, delta)`。世界保存注册顺序；每次 `step` 使用注册列表快照，新注册系统下次运行，移除后通过当前列表检查跳过。与节点回调相比，调用方能明确控制更新时间。
- 无效实体的变更返回 `false`，读取返回 `null`；查询条件使用脚本类型数组。系统重复注册同一实例返回 `false`。

## Risks / Trade-offs

- [线性查询在大量实体时变慢] → 保持接口稳定，待实际负载出现后增加索引。
- [组件是可变引用，原地修改无法触发通知] → 本版不提供变更通知；调用方在下一次系统更新中读取当前对象。
- [GDScript 对脚本类型与循环引用较敏感] → 无界面导入和契约测试覆盖类加载与调用。

## Migration Plan

没有现有 ECS 调用方。回滚功能提交即可移除运行时与测试。
