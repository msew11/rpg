# Design

## Context

`GameHud` 动态构建 HUD，系统按钮现直连设置面板；`MainController` 已具备登录、选角和 `ClearGame` 生命周期。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 菜单与现有 HUD 使用同一坐标系，阻止菜单点击穿透，复用现有设置和场景清理入口。

**Non-Goals:** 不新增退出确认、真实登出协议或新的设置项。

## Decisions

- 在 HUD 最上层创建透明全屏输入遮罩和普通四按钮面板。相比原生弹窗，布局直接使用 HUD 坐标，不依赖嵌入子窗口和桌面缩放；遮罩消费外部点击并关闭菜单，Esc 同样关闭。
- 打开时按实际最小尺寸计算系统按钮上方位置并约束视口，窗口变化时收起，下次打开重新定位。选择条目前先收起并恢复焦点，避免返回页面后残留菜单。
- HUD 发出返回登录、选角和退出请求，由 `MainController` 执行。保留本次成功登录结果用于返回选角，不重新硬编码演示凭据登录；返回登录时清空该结果。
- 保留角色面板的既有切换角色入口，统一走相同选角方法。

## Risks / Trade-offs

- [菜单点击误触世界] → 使用全屏输入遮罩，并通过真实视口输入测试验证外部点击不产生移动。
- [返回后旧会话或设置串用] → 复用 `ClearGame`，测试重新登录、切换男女角色及设置隔离。
- [退出操作提前结束测试] → 在独立冒烟进程的最后一步触发退出，验证正常退出码和已完成的前置断言。
