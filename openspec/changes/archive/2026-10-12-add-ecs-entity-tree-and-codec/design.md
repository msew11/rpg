# Design

## Context

`EcsWorld` 用 `IEcsWorldData` 管理实体与组件，销毁时目前只删除单个 ID。具体文件格式与会话仓库属于开发层。

## Goals / Non-Goals

**Goals:** 通用父子关系在共享数据实例中保持；销毁整棵子树；提供组件双向字符串入口。

**Non-Goals:** 文件读写、落地失败策略、世界区块或怪物行为。

## Decisions

- 在 `IEcsWorldData` 增加子到父的索引；`EcsWorld` 创建带父实体的子实体并查询直接子实体。销毁时先收集子树，再删除组件、关系与实体。无效父实体通过返回 0 表示失败，实体 ID 从 1 开始。
- `EcsComponent` 的默认落地方法返回 `null`，默认恢复方法对有数据输入报告不支持。具体组件覆盖方法；核心不进行反射构造或规定外层文件格式。
- 保留现有 `CreateEntity()` 作为根实体创建入口；新增重载避免破坏现有调用方。

## Risks / Trade-offs

- [递归树可能很深] → 迭代收集子树，避免调用栈增长。
- [实体关系与组件索引不一致] → 创建和销毁在同一世界操作中维护索引，核心测试覆盖共享数据和级联。
