## Context

当前 `EcsWorld` 直接读写 `DataEcsWorld` 的内部集合，且有无参、具体数据和单例仓库三种构造入口。核心数据类必须迁出时，核心不能继续引用它。

## Goals / Non-Goals

**Goals:** 保留实体和系统行为；将数据实例所有权交给调用方；核心只定义状态结构契约。

**Non-Goals:** 持久化、并发控制和新 ECS 行为。

## Decisions

- 使用 `IEcsWorldData` 名称。它描述状态数据契约；`Adapter` 通常表示已有接口之间的转换，这里没有转换。
- 接口公开下一个 ID、有效实体集合和组件索引的读写入口，`EcsWorld` 继续执行实体规则。此变更保持现有状态结构，不引入额外抽象层。
- 移除无参和仓库构造入口。核心不创建具体数据，也不依赖具体仓库。调用方从仓库读取数据后传给世界。

## Risks / Trade-offs

- 接口暴露可变集合，需要实现方维持状态一致；这与现有数据结构相同，后续若需持久化边界可另行设计。
- 构造 API 发生变化，开发层须同步迁移。
