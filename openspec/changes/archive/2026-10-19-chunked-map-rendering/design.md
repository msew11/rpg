# Design

## Context

参见 proposal.md。当前 `MapView` 在每次 `_Process` 都请求 `_Draw`，每帧重新提交全部候选瓦片的 CanvasItem 绘制命令。地图由启动配置加载，此阶段没有运行时改格子的入口。

## Goals / Non-Goals

**Goals:** 限制活动地图节点数量；相机平移时复用绘制结果；跨范围及窗口变化时保持可见覆盖。

**Non-Goals:** 动态地块编辑、正式美术素材、地图数据格式或 ECS 行为变更。

## Decisions

- 使用 8×8 格的 `Node2D` 分块，每个分块在 `_Draw` 中按全局格坐标读取地块，以分块原点为局部坐标绘制。Godot 缓存 CanvasItem 命令，只有新分块需要生成命令。相比单个大画布，跨界只绘制少量新格；相比整图 TileMap，不引入整图节点或素材体系。
- `MapView` 保留 `Map` 属性并管理活动分块字典。每帧从画布逆变换取得视口四角，换算为逻辑坐标的保守包围矩形，再换算为分块索引并夹在地图内。范围不变时不增删节点；范围变化时保留交集、创建新增、释放移出。包围矩形虽多包含部分画面外格子，但避免等轴边缘漏格。
- 分块超出地图右、下边缘时只绘制有效格。窗口尺寸变化由相同的范围计算自动处理；节点随世界视图释放，不保留离屏分块缓存。

## Risks / Trade-offs

- [初次进入世界仍需绘制附近分块] → 性能验收排除首帧预热，另检查无明显持续卡顿。
- [跨分块时可能有单帧耗时尖峰] → 以 8×8 小分块限制每次新增绘制量，实机连续移动观察帧耗时。
- [保守矩形会绘制少量画面外格子] → 只实例化视口附近的分块，并在场景测试中检查数量上界。
