# Design

## Context

当前 `test_ground.gd` 绘制有限场地，ECS 保存连续位置，`DataSource` 已从 `main` 合入 `develop`，但尚无运行时提供方。见 proposal.md 与本 change 的区块能力 spec。

## Goals / Non-Goals

**Goals:** 用手工数据验证有限环形世界、按距离显示区块、同一次运行中的改动保留，以及逻辑和展示通过数据层交换状态。

**Non-Goals:** 不做磁盘存档、网络同步、完整地图编辑器、碰撞或最终美术；本原型的区块尺寸和区块数量不构成正式世界规模承诺。

## Decisions

- **tile / chunk 命名。** 单格地面称 tile（地块），`n × m` 个 tile 构成 chunk（区块）。`grid` 留给整张网格，避免把 `thunk` 与延迟计算术语混淆。
- **行走坐标与数据 ID 分离。** 玩家使用不回绕的连续世界坐标，镜头与投影据此更新。地块整数坐标经向下取整得到行走区块坐标，区块内坐标采用非负余数；行走区块坐标再对有限世界区块数取非负余数，得到规范区块 ID。负坐标使用相同规则。这样边界两侧可读取同一份数据而画面不跳跃。相比直接重置玩家坐标，逻辑和镜头更连续。
- **手工配置内容。** 用少量显式测试区块布局和草地／泥地占位纹理呈现区域差异。运行时只读配置并建立初始地块状态；不引入程序生成算法，也不假定最终制作方式。
- **`develop` 的单机数据提供方。** 一个具体 `DataSource` 提供方保存玩家与规范区块 ID 对应的状态。区块首次访问时从手工配置建立数据；离开显示范围只卸载表现，不销毁内存状态。对外读取可变数据时提供副本，修改后显式写入以触发变化通知。`main` 上的抽象与文档不改动。
- **逻辑和展示共用数据边界。** 本地会话和区块管理写入 `DataSource`；玩家视图、地面和镜头从其中读取状态。主场景只做输入采集与对象装配，不让地面视图直接依赖区块加载系统。现有 ECS 组件继续作为游戏逻辑结构，但通过数据提供方访问其权威值。
- **有限显示范围。** 以玩家所在的行走区块为中心维护有限邻域。当前加载的行走区块坐标放在数据层；展示按这些坐标读取规范 ID 的地块数据，在对应的行走位置绘制。区块状态与显示实例分开，回环时可出现数据 ID 相同但位置不同的显示实例。
- **调试覆盖层。** 左上角 Debug 面板持续提供“显示边缘线”和“显示雷达”两个开关；F3 是边缘线的快捷键，开关状态双向同步。边缘线默认关闭、雷达默认开启，Windows 导出仍能操作。用多层半透明描边表现发光，两个开关状态经本地数据提供方传递，不写入地块数据。测试地块切换使用临时操作键，后续玩法可替换。
- **视口雷达。** 在固定于左上角的 CanvasLayer 中按等轴屏幕方向绘制当前加载区块菱形，每个区块有清晰描边，玩家所在区块突出显示。玩家点固定在雷达中心，用箭头显示屏幕朝向；区块位置由连续世界位置与区块原点的差投影得到，随玩家移动而平移，跨边界时不跳动。雷达从 `DataSource` 读取加载列表、区块尺寸、玩家位置和朝向，不依赖区块加载器；回环后仍按行走区块位置排列，并可标注规范 ID。
- **雷达语义。** 雷达根据视窗四角反算行走区块范围，绘制覆盖整个雷达视窗的区块网格，其中实际加载的 3 × 3 用蓝色，其余用灰色。可见区块均标注规范坐标，网格裁切在雷达视窗内。玩家所在区块四边最后绘制为黄色，坐标放在区块内部；跨越规范 ID 从世界末端回到 0 的共享边使用紫色外侧线标记，保留黄色当前区块边缘。雷达底部列出颜色含义。
- **完整地图。** 按 M 打开覆盖视口的大地图，展示有限的 4 × 4 个规范区块及其测试地块、玩家回环后的相对位置和回环外边界。打开地图时由区块逻辑确保全部规范区块数据可读，地图视图只读 `DataSource`。鼠标左键拖动仅改变地图画布偏移，不改变玩家位置；再次按 M 关闭。

## Risks / Trade-offs

- 有限环形世界不是内容无限增长 → 分离行走坐标和规范数据 ID，明确本次只验证无限行走体验。
- 远距离持续行走可能触及浮点精度 → 本原型测试多个回环；长期运行时再评估坐标重基准，且不改变规范 ID 规则。
- 同一规范区块可能同时出现在显示邻域的不同位置 → 展示实例以行走区块坐标区分，状态仍共享规范 ID。
- 同步数据契约尚未规定远端延迟 → 本次只提供单机内存实现；网络适配与权威性由后续 change 决定。

## Migration Plan

保留 `scenes/main.tscn` 入口，将固定地面视图替换为区块视图。回退只需恢复原场景与本次新增代码、手工数据；没有持久化数据迁移。
