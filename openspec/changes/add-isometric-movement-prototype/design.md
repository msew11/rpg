# Design

## Context

`scenes/main.tscn` 目前只是文字占位场景。项目已确定 Godot 4.7.2、GDScript、单人先行、未来 MMO、连续自由移动、屏幕方向操作与自建最小 ECS；可见行为见本 change 的两个 delta spec。

## Goals / Non-Goals

**Goals:** 让模拟状态独立于 Godot 节点生命周期，同时以真实的 CC0 等轴素材验证移动方向、地面比例和镜头观感。保留以后用服务器会话替换本地会话、用正式美术替换占位视图的边界。

**Non-Goals:** 不建通用 ECS 框架、网络协议、区块流式加载、存档、障碍碰撞或最终角色动画。

## Decisions

- **最小数据 ECS。** 使用稳定整数实体 ID，将位置、移动意图、速度和八方向朝向保存在无节点引用的数据容器中；移动系统只读写这些组件。先实现本原型需要的实体创建、组件访问与固定步长更新，不引入插件或抽象查询框架。相比把状态放进角色节点，这允许视图销毁后从同一实体状态重建。
- **本地会话边界。** 输入层把每帧采集的键盘状态转成玩家移动命令；本地会话在固定模拟步中应用命令并提供位置、朝向状态供视图读取。展示节点不得成为权威位置来源。未来服务器可以接管会话职责，但这次不制定传输格式或承诺跨语言直接复用。
- **逻辑坐标与投影分离。** ECS 保存连续的地面平面坐标。展示层集中配置等轴基向量，并将逻辑位置投影到画面；屏幕方向输入经逆投影转换为地面方向，再在逻辑坐标中归一化，确保斜向不增加逻辑移动速率。朝向依据非零屏幕输入的八方向确定，静止时保持上次朝向。
- **有限测试地面与可替换视图。** 第一段只放置足以覆盖移动验收范围的固定占位地面，不实现区块生命周期。地面渲染根据地块类型选择纹理；玩家视图以脚底为定位锚点，只接收实体位置和朝向。镜头跟随投影后的玩家位置。后续替换地块纹理或玩家视觉子节点，不应修改 ECS 组件或移动系统。
- **CC0 素材选择节点。** 在导入素材前，由用户从许可明确为 CC0 的 2D 等轴包中选定具体包；实施时只导入原型实际使用的资源，并记录原始页面、许可证和使用文件。未确认包名不写入玩法或架构约束；角色可先用清晰的方向标记验证八方向，不假定候选素材具有八方向动画。

## Risks / Trade-offs

- 有限测试地面不能证明大世界加载能力 → 区块加载与状态恢复保持为下一独立 change，并复用本次的逻辑坐标与实体 ID。
- 自建 ECS 可能在实体规模增大后需要更高效的存储 → 原型只覆盖移动；达到实际性能瓶颈后再测量和替换内部实现。
- 等轴投影使不同方向的屏幕像素速度看起来不同 → 验收以逻辑世界速率一致、屏幕方向正确为准，并在原型体验后调整投影比例或视觉节奏。
- 具体素材包尚未选定 → 不在选择完成前导入第三方资源；选择不会改变移动和会话边界。

## Migration Plan

实施时用新世界场景替换文字占位内容，保留 `scenes/main.tscn` 作为项目入口。回退可恢复该场景和本次新增代码、资源，不需要迁移存档。

## Open Questions

- 具体使用哪套 CC0 等轴地面素材？用户已决定在实施前选择；本 change 的行为要求与模块边界不依赖包名。
